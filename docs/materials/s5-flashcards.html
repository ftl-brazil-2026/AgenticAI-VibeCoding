Compare AI approaches and architecture layers

“Traditional AI” covers several approaches. Generative AI describes a capability; an agent describes how a system chooses and carries out actions.

Practice a team task

Manager → Coder → QA → Manager review. Follow the course’s CrewAI example to propose a function that adds two numbers. Three agents carry out four sequential tasks; the Manager is reused for the final review.

This browser walkthrough shows scripted examples. The linked notebook runs real CrewAI with local fixture responses and no provider API. QA compares a supplied code fixture; it does not execute the proposed code.

Inspect roles, actions and task dependencies
  • 1. Manager · brief — scope the request; return WorkOrder. No tools.
    • 2. Coder · code — consume the brief; return CodePatch. In tool scenarios, its fixture calls the injected code tool once per attempt.
      • 3. QA · qa — consume the patch; return QAReport with the patch hash and fixture comparison. No tools.
        • 4. Manager · review — consume brief, patch and QA evidence; return ManagerDecision. No tools.
  • Python wrapper · run_team — check task IDs, current patch hash, QA pass and Manager approval. Retry recognized failures using a fresh crew, up to three total kickoffs.

Each task uses output_pydantic and a strict guardrail. Native agent and guardrail retries are disabled. Dependencies flow through Task.context; execution uses Process.sequential.
